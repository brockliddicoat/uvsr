# AGFX texture transfers

source: AGFX `f91b108a111d2ca3ca4b6586b6cb5dd750064fd7`. [the manifest](texture-sources.json) pins both source test files and unchanged PNG/binary goldens. AGFX's MIT notice applies. this extends the [primary slice](primary-slice.md), with two source behavior groups and four additional exact controls. it does not complete the full texture API or the meaningful Ez lifecycle inventory.

| source behavior | Rust mapping and decisive oracle |
| --- | --- |
| `agfxTextureCreate/Destroy/GetInfo`, committed 2D allocation | `Device::texture`, borrowed `Texture`, `Texture::info`. one mip/layer, RGBA8_UNORM or RGBA32_FLOAT, owned same-format storage view. exact format/type/tiling/usage capabilities, extent limits, memory type and dedicated allocation are checked. [U-017](../../UNSAFE.md#u-017-owned-2d-storage-texture-and-complete-transfers) records native ownership |
| buffer-to-image copy, image region and row pitch | `Device::copy_buffer_to_texture` with `TextureCopy`. the source 128x128 gradient/checker is overwritten by a 32x32 asymmetric patch at(16,64). complete readback matches every byte of the original decoded `copy_buffer_to_texture.png`, including alpha |
| image-to-buffer copy and destination offset | `Device::copy_texture_to_buffer`. the source 64x64 XOR/gradient writes at offset256. all16640 bytes match the original `copy_texture_to_buffer.bin`, including the unchanged0xAB prefix |
| copy resource states and completed readback | native TRANSFER_SRC/DST_OPTIMAL transitions bracket each transfer, with GENERAL on return. explicit completion precedes CPU access/destruction. source C/Cpp/Ez image/data results share these mappings, while broader Ez state/frame/residency behavior remains open |
| additional exact controls | RGBA8 clear endpoints, signed/HDR RGBA32 float round trip, exact float clear, and different padded upload/readback row pitches with protected prefixes/gaps/suffixes |

the six native cases pass in Debug and Release with corresponding byte hashes identical and zero Khronos core/synchronization diagnostics. twelve invalid-use controls reject zero/overflow dimensions, uninitialized resources, partial first initialization, image overrun, invalid pitch, untouched uninitialized prefixes/row padding, foreign-device owners and misaligned float-texel offsets. three CPU cases cover size overflow, last-row footprint and padding coverage. five Python evidence controls reject stale/empty/skipped/duplicated records, mutated color/alpha/float/sentinel bytes, broken completion and missing validation.

`TextureCopy` preserves byte offsets and integral row pitch. offsets align to the format's full texel block, which is16 bytes for RGBA32_FLOAT. row pitch must fit the native signed limit. the checks follow Vulkan's [copy validity rules](https://docs.vulkan.org/spec/latest/chapters/copies.html), including VUID07975 and VUID09108. complete first initialization is a Rust safety adaptation. subsequent partial copies preserve all untouched data. no invalid native command is used as a negative test.

buffers and images share a checked native allocation budget. each allocation checks the selected heap and device size limits, and resource leases keep intentionally forgotten native children and their parent device alive. three additional CPU cases cover count exhaustion, cleanup rollback, forgotten leases and size limits. [U-010](../../UNSAFE.md#u-010-rust-vulkan-device-buffer-and-synchronous-submission) records these ownership rules.

this increment uses one existing synchronous queue and adds no dependency to the Rust owner. the external oracle runner requires Pillow to decode the frozen PNG. no compiler, shader, resource heap or backend adapter change is involved. later increments add [sampled resources and configurable usage](sampling.md), [render targets](raster.md) and [whole-image format views](format-views.md). mip/layer/cube/3D images, remaining formats, general view handles, image-to-image/blit operations, placed resources and native escape contracts remain required in T024/T025. source mutable-view behavior and narrower creation flags are tracked in A-014. no performance improvement or Linux execution is claimed.
