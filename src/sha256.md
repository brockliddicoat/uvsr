# native SHA-256

[`sha256.h`](sha256.h) exposes borrowed memory or a null-terminated UTF-16 path,
a fixed lowercase digest and a stage/native-code result. failure preserves the
caller's digest. successful calls clear an earlier result. a null memory pointer
is accepted only for an empty input; overflowing address ranges are rejected.
callers still own input validity and lifetime.

[`sha256_win32.cpp`](sha256_win32.cpp) compiles once with exceptions disabled.
Windows CNG supplies SHA-256. the provider owns the hash-object buffer until
`BCryptDestroyHash`, and the algorithm provider is closed afterwards. this avoids
the old member-order bug that freed the caller-owned buffer before destroying its
hash handle. the null-buffer ownership option is part of the
[BCryptCreateHash contract](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptcreatehash).

file hashing retains the 1 MiB read size and read/write sharing. it checks file
open, buffer allocation, every read and final close before publishing the digest.
every early exit releases the buffer, file and CNG handles. input files must remain
stable for the desired hash identity; permitting shared writers does not provide
a file snapshot. CNG and Windows internals remain platform dependencies.

[`uvsr_command_line_tests.cpp`](../tests/uvsr_command_line_tests.cpp) preserves
known digests, the streamed boundary and failure/retry checks in both application
modes. object-size-query failures retire with that unused query. added cases cover
invalid inputs, unchanged output, allocation/close failures, a sharing violation,
an empty file and an independently computed boundary digest. asset and legal
validators retain their existing hashes. their caller-side text, filesystem and
exception transport remain separate migration work.
