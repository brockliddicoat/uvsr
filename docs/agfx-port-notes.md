# AGFX behavior and future Rust changes

this is the ongoing record of inherited behavior worth revisiting for efficiency or simpler Rust. source pin: AGFX `f91b108a111d2ca3ca4b6586b6cb5dd750064fd7`, with inspected files frozen in the [source manifest](../tests/parity/primary-slice-sources.json). the [slice mapping](../tests/parity/primary-slice.md) owns required parity and oracles.

as of 2026-09-19, the Rust slice is unimplemented. these are **observed source behaviors and candidate changes**, not claims that the Rust port already inherited them or that an optimization was measured. update each entry when its Rust owner exists. preserve source-visible behavior where required, but do not copy unsafe interfaces or cross-backend restrictions merely for line-by-line similarity.

| id / source behavior | initial port decision and reason | future candidate / evidence needed |
| --- | --- | --- |
| A-001. [test transfer helpers](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx_tests/test_gpu.cpp#L147) allocate temporary command/fence and staging resources, submit, then block. [Ez uploader](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_ez.hpp#L501) batches copies but waits in `Flush` before freeing staging. | preserve completed upload/readback results and retirement ordering. synchronous fixture helpers are useful correctness controls, not a required runtime-wide scheduling policy. | consider reusing recording/staging resources or retiring them by completion token. first measure allocations, submissions, CPU wait time, peak memory and end-to-end latency. retain exact bytes and failure cleanup. no speedup is established. |
| A-002. [Vulkan submission](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L1504) builds a `std::vector<VkCommandBufferSubmitInfo>` for each submission. | preserve submitted buffer order and ownership until completion. a Rust `Vec` is a simple baseline if needed. | for a measured common single-buffer path, use one stack value. consider reused storage for larger batches only if allocation profiles justify it. compare submitted work, allocations and host cost. |
| A-003. [buffer-view handles](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2714) expose descriptor slots as `uint64_t`, while the [compute test](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx_tests/tests/test_compute_multi_dispatch_buffer.cpp#L97) casts to the 32-bit shader field. | keep the shader ABI and descriptor identity explicit. Rust should use checked conversion and distinct host/index types from the start, preserving exhaustion handling. | review whether a narrower public index type removes conversions and invalid states without losing required source behavior. test maximum valid index, exhaustion, foreign-device handles and stale reuse. this is an API simplification candidate, not a measured throughput gain. |
| A-004. [Cpp mapping](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx.hpp#L852) exposes `void*` and `MappedBuffer::As<T>()`, with RAII unmapping. | preserve mapping lifetime and cleanup. ordinary Rust callers should receive a bounded borrowed byte view when its validity and completion conditions are enforced. arbitrary typed views must not become an unchecked safe API. | evaluate whether a byte-oriented guard eliminates repeated map/unmap bookkeeping. keep typed conversion separately checked for size, alignment, initialization and valid representations. safety obligations apply during the first implementation, not after optimization. |
| A-005. [buffer UAV barrier](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2177) covers the whole buffer with compute write-to-read/write masks. | retain the dependency between the four dispatches in the source oracle. do not remove barriers simply because the fixture is small. | consider explicit byte ranges or batching barriers only for measured workloads that benefit. prove access coverage and ordering with validation and deterministic output before comparing GPU timings. no avoidable stall is yet measured. |
| A-006. [host memory selection](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L1221) requires `HOST_COHERENT`. [readback allocation](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2388) first requests `HOST_CACHED`, then retries without caching, retaining coherence. | preserve the coherent-memory requirement and cached-readback preference in the initial slice, with explicit allocation failure if no compatible type exists. completion still precedes CPU access. | consider a non-coherent fallback only for demonstrated device compatibility or measured transfer cost. it needs explicit flush/invalidate ownership and atom-aligned range handling, plus exact readback tests on the actual selected memory type. no portability failure or speedup has been observed. |
| A-007. the [queue-ownership comment](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L1519) describes concurrent resource sharing, but [buffer creation](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2353) sets `VK_SHARING_MODE_EXCLUSIVE`. buffer barriers use ignored family indices. | this is an observed comment/implementation mismatch, not a reproduced GPU failure. the initial Rust slice should own one queue family and enforce that boundary explicitly. do not infer transfer support from the source comment. | before exposing cross-family use, choose and implement matching sharing or ownership-transfer rules. test distinct family availability, host-side rejection of unsupported transfers, completion and deterministic output with native validation. clean up the Rust contract from the start rather than inheriting the contradictory comment. |
| A-008. [agfxSlotAllocator](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L43) initializes a bitmap and eagerly fills a free-index vector. [device construction](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L167) does this for fixed capacities of 400,000 resources, 2,000 samplers and eight acceleration structures. initial allocation pops the highest index, exhaustion returns UINT64_MAX, and duplicate or out-of-range frees are ignored. | preserve unique live indices, explicit exhaustion and completion before reuse. define invalid-free handling in the Rust ownership contract. fixed maximum capacity and initial index order are source behavior to assess, not automatically required allocation policy. | consider a lazy next-unused index plus a recycled-index list. retain or replace the bitmap according to the checked ownership contract rather than removing it as redundant without proof. compare startup CPU time, allocated metadata, peak live slots and reuse cost. test exhaustion, uniqueness, valid reuse and rejected invalid frees. no measured cost or Rust implementation yet. |
| A-009. [agfxSamplerCreate](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2627) treats comparison function ALWAYS as comparison disabled. every other function enables comparison. the same field therefore cannot request an enabled always-pass comparison sampler. | preserve the source convention in parity fixtures. keep the distinction between ordinary and comparison sampling explicit in Rust. | consider `Option<CompareOp>` or an equally small enum so disabled comparison and enabled Always are distinct states. map source ALWAYS to None when translating old fixtures. test ordinary sampling, explicit Always comparison and a nontrivial comparison with deterministic depth values and correct shader operations. source-observed API ambiguity, not a measured runtime defect or speedup. |
| A-010. [Vulkan sampler creation](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2639) forces anisotropy off, with a source comment attributing this to the DirectX backend's non-anisotropic filters and shared goldens. | retain non-anisotropic settings for the source parity cases and the initial slice. this historical cross-backend choice is not evidence of a Vulkan limitation. | if a real workload needs anisotropy, expose an explicit capability-checked Vulkan setting with queried limits while keeping the parity configuration fixed. compare image quality and GPU time at fixed views/filter settings and reject unsupported settings. no current Rust owner, measured benefit or implementation commitment. |

| A-011. [agfxRenderPassSetViewport](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2814) adds height to viewport Y and submits negative height. the source comment links this to DirectX/Metal coordinates, no shader invert-Y flag, and shared goldens. | preserve that convention for AGFX parity. the actual NGAPI cube is a different caller with positive viewport height and an explicit transform, so its result is not AGFX coordinate parity. | make clip coordinates, framebuffer origin, viewport sign and winding explicit in the Rust contract. consider a native positive-height path only where the caller needs it, with one documented conversion. test asymmetric geometry, both windings with culling, viewport/scissor offsets and depth before changing defaults. this is a source-observed contract-clarity candidate, not a measured defect or optimization. |

update these notes at coherent port checkpoints and link their IDs from affected source mappings. this is a focused record of opportunities, not a second implementation task ledger. only measured costs should become optimization claims. a useful Rust ownership simplification can be justified by a smaller, clearer contract and equivalent tests without inventing a performance benefit.
