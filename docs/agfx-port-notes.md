# AGFX behavior and future Rust changes

this is the ongoing record of inherited behavior worth revisiting for efficiency or simpler Rust. source pin: AGFX `f91b108a111d2ca3ca4b6586b6cb5dd750064fd7`, with inspected files frozen in the [source manifest](../tests/parity/primary-slice-sources.json). the [slice mapping](../tests/parity/primary-slice.md) owns required parity and oracles.

as of 2026-09-19, the Rust slice is unimplemented. these are **observed source behaviors and candidate changes**, not claims that the Rust port already inherited them or that an optimization was measured. update each entry when its Rust owner exists. preserve source-visible behavior where required, but do not copy unsafe interfaces or cross-backend restrictions merely for line-by-line similarity.

| id / source behavior | initial port decision and reason | future candidate / evidence needed |
| --- | --- | --- |
| A-001. [test transfer helpers](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx_tests/test_gpu.cpp#L147) allocate temporary command/fence and staging resources, submit, then block. [Ez uploader](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_ez.hpp#L501) batches copies but waits in `Flush` before freeing staging. | preserve completed upload/readback results and retirement ordering. synchronous fixture helpers are useful correctness controls, not a required runtime-wide scheduling policy. | consider reusing recording/staging resources or retiring them by completion token. first measure allocations, submissions, CPU wait time, peak memory and end-to-end latency. retain exact bytes and failure cleanup. no speedup is established. |
| A-002. [Vulkan submission](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L1504) builds a `std::vector<VkCommandBufferSubmitInfo>` for each submission. | preserve submitted buffer order and ownership until completion. a Rust `Vec` is a simple baseline if needed. | for a measured common single-buffer path, use one stack value. consider reused storage for larger batches only if allocation profiles justify it. compare submitted work, allocations and host cost. |
| A-003. [buffer-view handles](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2714) expose descriptor slots as `uint64_t`, while the [compute test](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx_tests/tests/test_compute_multi_dispatch_buffer.cpp#L97) casts to the 32-bit shader field. | keep the shader ABI and descriptor identity explicit. Rust should use checked conversion and distinct host/index types from the start, preserving exhaustion handling. | review whether a narrower public index type removes conversions and invalid states without losing required source behavior. test maximum valid index, exhaustion, foreign-device handles and stale reuse. this is an API simplification candidate, not a measured throughput gain. |
| A-004. [Cpp mapping](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx.hpp#L852) exposes `void*` and `MappedBuffer::As<T>()`, with RAII unmapping. | preserve mapping lifetime and cleanup. ordinary Rust callers should receive a bounded borrowed byte view when its validity and completion conditions are enforced. arbitrary typed views must not become an unchecked safe API. | evaluate whether a byte-oriented guard eliminates repeated map/unmap bookkeeping. keep typed conversion separately checked for size, alignment, initialization and valid representations. safety obligations apply during the first implementation, not after optimization. |
| A-005. [buffer UAV barrier](https://github.com/AmelieHeinrich/agfx/blob/f91b108a111d2ca3ca4b6586b6cb5dd750064fd7/src/agfx/agfx/agfx_vulkan.cpp#L2177) covers the whole buffer with compute write-to-read/write masks. | retain the dependency between the four dispatches in the source oracle. do not remove barriers simply because the fixture is small. | consider explicit byte ranges or batching barriers only for measured workloads that benefit. prove access coverage and ordering with validation and deterministic output before comparing GPU timings. no avoidable stall is yet measured. |

for new entries, record the source symbol/pin, actual Rust owner or `not implemented`, reason for keeping the behavior, proposed change, evidence classification, decisive correctness/performance check and disposition. use `candidate`, `retained`, `changed` or `rejected`, with a commit/evidence link when resolved. the entries above are all `candidate` with Rust owner `not implemented`.

update these notes at coherent port checkpoints and link their IDs from affected source mappings. this is a focused record of opportunities, not a second implementation task ledger. only measured costs should become optimization claims. a useful Rust ownership simplification can be justified by a smaller, clearer contract and equivalent tests without inventing a performance benefit.
