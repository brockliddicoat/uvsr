# build and shaders

this is the canonical developer build, shader, renderer package, and release
gate reference. the launcher has a separate build entry point, but it consumes
the renderer package defined here.

## build identity

use a recursive checkout with exact submodule revisions. build outside the
repository. generated builds, dependency downloads, caches, staging, and
artifacts do not belong in Git.

before reusing a build tree, compare its source lineage, generator, toolchain,
architecture, configuration, options, and dependency state with the requested
build. reconfigure after build system, option, toolchain, or dependency changes.
clean only after proven contamination. use a separate tree for concurrent work
and for developer and production configurations.

the source and settings identity is generated by
[`SourceIdentity.cmake`](../cmake/SourceIdentity.cmake),
[`RefreshBuildIdentity.cmake`](../cmake/RefreshBuildIdentity.cmake), and the C++
identity generator. a production build requires a clean exact source commit.
`UVSR_RENDERER_RELEASE_SEQUENCE` is package metadata. changing it does not grant
publication authority.

## developer build

use Visual Studio's x64 toolchain and CMake 3.24 or later. Python is not a first
party build dependency.

```powershell
$dev = 'C:/uvsr-build/dev'
cmake -S . -B $dev -A x64 -DBUILD_TESTING=ON -DUVSR_RENDERER_RELEASE_SEQUENCE=16
cmake --build $dev --config Release
ctest --test-dir $dev -C Release --output-on-failure
```

replace the example path and unissued sequence with task specific values. a
focused iteration may build and run only affected targets. run the complete
applicable developer gate once before integration or handoff.

developer builds retain the production feature set. they may add validation,
the DirectX 12 debug layer, diagnostic commands, and tests. they are not package
or release proof.

## direct dependencies

the root CMake graph owns exact DirectX 12 dependencies through the `Direct*`
modules. NVRHI and ImGui use direct checked out pins. DXC, DirectX Headers,
Agility SDK, cgltf, stb, JsonCpp, TinyEXR, and GLFW use exact
source, archive, or runtime identities recorded by their modules.

[`VerifyDirectDependencyState.cmake`](../cmake/VerifyDirectDependencyState.cmake)
checks revisions, archive hashes, source trees, licenses, and staged patches.
patches are applied only to build tree copies. never edit Donut or a pinned
dependency to make a local build pass.

Donut, JsonCpp, TinyEXR, and GLFW are retained consumers. direct pinning does
not authorize Donut detachment or removal of a dependency that it still uses.

## shader contract

pinned DXC compiles all active HLSL through
[`DirectXShaderCatalog.cmake`](../cmake/DirectXShaderCatalog.cmake). the compiler
input is a task catalog such as `src/shaders.cfg`, the retained Donut shader
catalog. task catalogs describe compilation. they
are not package inventories.

[`shader_blob.h`](../src/shader_blob.h) and
[`shader_blob.cpp`](../src/shader_blob.cpp) own the runtime blob format and
lookup. [`shader_blob_builder.cpp`](../tools/shader_blob_builder.cpp) owns
dependency scanning and deterministic packing. each task produces a DXIL object
and depfile. a content stable catalog produces one family blob. do not introduce
a second blob format, compiler wrapper, or broad rebuild stamp.

[`runtime-shader-inventory.def`](../cmake/runtime-shader-inventory.def) is the
sole shipped shader allowlist. it covers both first party and remaining
framework blobs. [`SyncRuntimeShaderBundle.cmake`](../cmake/SyncRuntimeShaderBundle.cmake)
copies exact inputs, verifies hashes, and removes stale outputs. remove an
inventory row only after its runtime consumer and compile task are gone. add a
row only with a proven runtime consumer.

when a shader input changes, rebuild the affected bundle and its consumers. do
not restage assets or rebuild unrelated shaders. a shader change is complete
only after direct compilation, relevant reflection or known answer checks,
runtime inventory validation, and the affected rendered path pass.

## renderer package

production uses a separate tree with tests disabled:

```powershell
$prod = 'C:/uvsr-build/prod'
cmake -S . -B $prod -A x64 -DBUILD_TESTING=OFF -DUVSR_RENDERER_RELEASE_SEQUENCE=16
cmake --build $prod --config Release --target uvsr-renderer-package
```

the target creates `artifacts/uvsr-renderer-windows-11-x64.zip`. the archive has
no wrapper directory. its roots are `package-manifest.json`, `bin`, and `media`.
it contains only `uvsr-engine.exe`, required runtime DLLs, canonical settings,
the exact shader bundle, retained assets, and applicable notices and licenses.
it contains no source, tests, symbols, debug layers, Git, CMake, compilers,
SDKs, interpreters, or benchmark tools.

[`runtime-asset-map.def`](../cmake/runtime-asset-map.def) is the
protected retained media and governing notice source to package map. legal
mappings in `cmake/RuntimeLicenseMappings.cmake` own the full
runtime notice set.

[`renderer_package_contract_validator.cpp`](../tools/renderer_package_contract_validator.cpp)
generates canonical settings and the manifest from the compiled C++ schema,
checks production PE metadata against the clean source identity, and binds each
file by path, size, and SHA-256. it verifies the stage and extracted archive.
the native launcher's package inspection checks signed identity and the exact
archive independently. both validators consume the authoritative C++ settings
schema and generated inventories.

## release gate

the developer integrity gate verifies the [postmortem manifest](postmortem/publication-manifest.tsv)
and discovers unrepresented reports in registered local worktrees. package builds
and CI additionally require those exact files in the committed source candidate.
run `cmake -DUVSR_REQUIRE_COMMITTED=ON -P cmake/VerifyPostmortems.cmake` before
an authorized publication. the check never stages, commits, or uploads files.

the full gate is:

1. exact dependency verification;
2. complete developer Release build and CTest;
3. clean production Release package build;
4. independent validation of the stage and extracted CMake archive;
5. launcher archive round trip, install, update, repair, rollback, ownership,
   process, shortcut, and uninstall contracts;
6. independently computed SHA-256 for `uvsr-launcher.exe`, the archive, and the
   packaged `uvsr-engine.exe`;
7. exact package smoke on local DXR hardware with source, settings, scene,
   camera, adapter, driver, package, and capture identity; and
8. PIX or equivalent debug layer evidence for barrier, lifetime, ray tracing,
   shell, or Donut boundary changes.

hosted CI builds and validates but does not publish. feed creation, code signing,
release creation, upload, and endpoint changes are separate authorized actions.
the production private key and signing certificate are not repository inputs.

for local evaluation, manually dispatch Windows Renderer Package with
`export-runtime-bundle` enabled. after every hosted gate passes, it retains the
complete renderer ZIP, launcher, and hash records for one day. extract the whole
renderer ZIP and open `bin/uvsr-engine.exe`, preserving its sibling runtime files
and the adjacent `media` directory. copying the executable alone cannot run the
engine. this candidate export does not publish a release or a signed feed.
